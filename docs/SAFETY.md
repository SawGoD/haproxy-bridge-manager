# Инварианты безопасности

- Приложение работает локально. Разработка не обращается к продуктивному `/opt/haproxy`.
- Документ HAProxy сохраняет оригинальные строки; неподдерживаемая конструкция не должна интерпретироваться как безопасно редактируемая.
- Перед записью обязательны проверка хеша исходника, резервная копия и проверка именно кандидата настоящим HAProxy.
- Атомарная замена выполняется в каталоге исходника с синхронизацией файла и каталога.
- Docker validator использует immutable image ID из inspect. Неизвестные entrypoint и аргументы запуска блокируются.
- Single-file bind после атомарной замены требует пересоздания контейнера. Restart не считается подтверждением обновления.
- Graceful reload разрешается только после проверки управляющего процесса и механизма reload. В Docker проверяются PID 1, флаг master-worker, актуальность файла и появление нового worker после USR2; при невозможности проверки операция блокируется. В Native graceful пока заблокирован.
- Наличие UP в статистике не доказывает, что конкретный сервер обслуживает соединения. Без наблюдаемых соединений активный сервер — UNKNOWN.
- TCP connect time — не ICMP ping; TCP/TLS не подтверждает авторизацию VLESS+REALITY.
- Автоматический rollback допустим только к проверенной рабочей конфигурации. Случайный последний backup такой гарантией не является.

## Основания

- HAProxy 3.2 Configuration Manual: https://docs.haproxy.org/3.2/configuration.html
- HAProxy 3.2 Management Guide: https://docs.haproxy.org/3.2/management.html
- Официальный Docker entrypoint: https://github.com/docker-library/haproxy/blob/master/docker-entrypoint.sh
- Ограничение single-file bind: https://github.com/moby/moby/issues/6011

Без `option allbackups` выбирается первый работоспособный резервный сервер при отсутствии доступных обычных серверов. Для приоритета IPv4 → IPv6 → NetBird нужен один обычный сервер, упорядоченные backups и health checks. Это правило выбора новых соединений; существующие TCP-сессии на резервном сервере автоматически не мигрируют. Несколько обычных серверов означают балансировку, а `allbackups` меняет выбор резервов.
